# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose credentials, execute unintended commands, overwrite files outside ProveIt-owned paths, or publish sensitive evidence.

Use GitHub's private vulnerability reporting feature when it is enabled for the repository. Include the affected version, operating system, reproduction steps, impact, and any suggested mitigation.

## Supported versions

Security fixes are applied to the latest release. Users should update by rerunning the installer from the latest trusted release.

## Evidence safety

Automatic redaction is a defense-in-depth feature, not a guarantee. Review generated evidence before sharing it. Do not intentionally pass production secrets to test commands or reports.
